# Spotlight

> **Discover what's happening around you.**
> A map-first React frontend and a TypeScript/Express backend that surface nearby
> live events and venue details from the Ticketmaster Discovery and Google Places APIs.

## What it does

- Resolves your location via browser geolocation (falls back to Ann Arbor, MI)
- Renders every nearby event venue as a marker on an interactive Mapbox map
- Groups all events at the same venue into a single marker with a scrollable popup
- Filters events by a date range
- Enriches the selected venue with its Google Places rating, review count, and open/closed status
- Caches backend responses so repeat queries are served in milliseconds

## How the event search works

A naive geo search against Ticketmaster returns at most 100 events and skews
toward the busiest venues. `searchByLocation` runs two searches concurrently and
merges them:

- **Track A — direct geo search.** One `events.json` call filtered by
  `latlong` + `radius`. Surfaces the high-volume venues.
- **Track B — venue-first search.** One `venues.json` call for the 50 nearest
  venues, then one `events.json` call per venue. Catches smaller venues that
  never make the first page of a direct search.

Both tracks are issued through `Promise.all` (52 concurrent requests), deduplicated
by event ID, and any track that fails is skipped rather than failing the request.
On a Manhattan search this lifts results from ~100 events to ~340.

The frontend then groups events by venue coordinate rounded to 4 decimal places
(~11m), because Ticketmaster reports slightly different coordinates for different
events at the same building. Measured against live data:

| City | Events | Markers after grouping | Reduction |
| --- | --- | --- | --- |
| New York | 337 | 50 | 85% |
| Chicago | 388 | 44 | 89% |
| Los Angeles | 318 | 61 | 81% |
| Seattle | 265 | 32 | 88% |
| Ann Arbor | 115 | 8 | 93% |

## Caching

`backend/src/config/cache.ts` exposes one `cacheService` over two backends. If
`UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` are set, Upstash Redis is
used; otherwise, or after Redis fails once, it falls back to an in-process TTL
cache. Failures disable Redis for the life of the process rather than paying a
network timeout on every subsequent request.

Responses are cached for 1 hour. Measured cold vs. warm on the same query:

| City | Cold | Cached |
| --- | --- | --- |
| New York | 1.16s | 2.7ms |
| Chicago | 0.85s | 3.2ms |
| Los Angeles | 0.90s | 2.0ms |
| Seattle | 0.70s | 1.6ms |

`GET /health` reports the active backend along with live hit/miss counts.

## HTTP API

| Method | Endpoint | Purpose |
| --- | --- | --- |
| GET | `/health` | Health check plus live cache stats |
| GET | `/api/ticketmaster/search` | Events near `latitude`/`longitude`; optional `radius`, `keyword`, `startDate`, `endDate` |
| POST | `/api/ticketmaster/events-for-venues` | Batch events for a list of `{ name, latitude, longitude }` places |
| GET | `/api/googlePlace/search` | Nearby places by `latitude`/`longitude`; optional `radius`, `type`, `keyword` |
| GET | `/api/googlePlace/venue` | Resolve one venue by `name` + coordinates; returns `null` when there is no confident match |
| GET | `/api/events/search` | Event search by `keyword` + `city` |

Every response is wrapped as `{ success, count?, data, source? }`, where `source`
indicates whether the payload came from the cache or the upstream API.

## Setup

### 1) Install

```bash
git clone https://github.com/pradeepg78/Spotlight.git
cd Spotlight

cd backend && npm install
cd ../frontend && npm install
```

### 2) Configure environment

Copy the templates and fill in your keys:

```bash
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
```

`backend/.env`:

```bash
PORT=3001
NODE_ENV=development
TICKETMASTER_API_KEY=your_ticketmaster_key
GOOGLE_PLACES_API_KEY=your_google_places_key

# Optional. Leave blank to use the in-memory cache.
UPSTASH_REDIS_REST_URL=
UPSTASH_REDIS_REST_TOKEN=
```

`frontend/.env`:

```bash
REACT_APP_API_BASE_URL=http://localhost:3001
REACT_APP_MAPBOX_TOKEN=your_mapbox_token
```

> The backend must run on a different port than the CRA dev server, which uses
> 3000. `REACT_APP_API_BASE_URL` has to match the backend's `PORT`.

### 3) Run

```bash
# terminal 1
cd backend && npm run dev

# terminal 2
cd frontend && npm start
```

Open `http://localhost:3000`.

## Known limitations

- MongoDB is wired up but not bootstrapped; nothing is persisted between runs.
  All state is either fetched live or cached.
- There is no authentication; every endpoint is public.
- The in-memory cache is per-process, so it does not survive a restart and is not
  shared across instances. Configure Upstash for that.
- Ticketmaster is the only event source, so coverage reflects theirs.
